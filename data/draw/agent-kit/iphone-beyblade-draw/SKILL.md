# iPhone 鏡像抽獎流程

版本：2026-10-03（工具中立版；上一版 2026-10-02 只寫 Codex 工具）

## 需要的能力（先確認，不要假設）

- 必須有能**看見並點擊本機 Mac 視窗**的畫面操作工具。各產品名稱不同（例如 Codex 的 Computer Use、Claude 的電腦操作／computer use 工具），以當下環境實際提供的工具為準。
- 目標視窗是 macOS 的「iPhone 鏡像輸出」App（bundle id `com.apple.ScreenContinuity`）。
- 沒有這類工具、只能文字對話、或只能操作遠端／雲端瀏覽器：告訴使用者缺少哪項能力並停止，**不聲稱能操作**。
- 本技能不自行提供任何控制工具。各環境的工具備註見文末「附錄」。

## 範圍

- 使用者要求開始或繼續後，處理目前篩選清單中的剩餘項目；不要自行變更地區、店家或其他篩選。
- 本流程是參加商品購買資格抽獎，不包括購買、付款、優惠券核銷或傳送訊息。
- 例外：參加按鈕寫「加入好友並參加抽獎」時，加入該店 LINE 官方帳號好友是參加的一部分，使用者已明確同意，直接按（見「參加按鈕的兩種寫法」）。
- 技能記錄本身不是未來操作的授權；在新的使用者要求下執行，已授權的同一批項目不重複詢問。

## 開始與位置

開始、恢復中斷或使用者調整顯示後，查看一次目前鏡像畫面，確認連線、目前是哪種畫面、篩選範圍、剩餘數量及按鈕座標。不要重新要求使用者示範已記錄的流程。

### 優先：👾 Agent 模式（網站 2026-10-02 起提供）

畫面右上角 👾 為選取狀態時，目錄一次只顯示一個品項：

- 上方是進度「第 N／M 項 · 剩 K 項」與範圍，中間一張品項卡（店家、型號、名稱），下面一顆大的綠色「抽籤」，位置固定。
- 從官方抽獎頁關閉回來後，目錄**會自動換下一項**，不必回清單找下一顆按鈕，也不用按「下一項」。
- 按鈕下方有狀態字：「開啟中…」「等待返回…」時按鈕是灰的、不要連點；「沒偵測到抽籤頁打開或返回」表示該項沒有成功開啟，再按一次「抽籤」重開同一項。
- 若回來後**沒有**換項（狀態字仍是同一項），不要自己判定已完成：先看狀態字，再決定重按或用卡片右上 ⋯ 的「跳過，稍後重試」。
- 若懷疑**多跳了一項**（例如途中切了 App），用 ⋯ →「上一項」回到原活動，再按「抽籤」。
- 全部走完會顯示「本次隊列已走訪完畢」，抽籤鈕會消失；有待重試項目時會出現「重試未完成項目」。
- 不在每一項開關 👾，也不要點 ⋯ 裡的其他項目，除非是上述復原情境。

以下座標是某次實測、約 322 × 718 的 App 截圖為基準，只是參考位置，不是所有視窗尺寸的通用座標：

| 動作 | x | y |

| 清單最上方綠色「抽籤」 | 276 | 303 |
| 抽獎頁底部藍色「參加抽獎」／「加入好友並參加抽獎」 | 161 | 665 |

**兩種模式都一樣**：目錄頁本身右上角也有叉叉／關閉入口；只能在官方抽獎頁關閉，避免把目錄關掉。

## 誤關目錄的實際失敗與必要修正

後續補抽曾多次誤點到整個網頁右上角叉叉。使用者明確指出這是錯誤，因此不可把固定座標長迴圈當成已驗證的可靠自動化。

- **打叉的唯一前提：確定按到了官方頁的參加按鈕**。按到之後就直接按官方頁右上角叉叉，不必再確認「處理中」、結果遮罩或中獎結果（使用者 2026-10-03 指定）。參加後出現結果遮罩也照樣直接打叉。
- 反過來，沒確定按到參加就不打叉：開啟項目失敗、畫面尚未載入、看不到參加按鈕、工具回報視窗被改動時，不可沿用之前的判斷去點叉叉——那時畫面可能還停在目錄。
- 「參加 → 關閉」在切換及中斷情境下曾不可靠；恢復後先看一次畫面，不要直接執行未檢查的三點連續循環。
- 若為避免誤關需要一次畫面確認，明確說明用途並保留必要確認；不要因使用者催促就繼續未知畫面的點擊。
- 截圖檔實測可能是 JPEG，即使標示為 image/png；讀取像素前按實際檔頭判斷格式。

## 參加按鈕的兩種寫法

- 官方抽獎頁底部的按鈕可能是「參加抽獎」，也可能是「**加入好友並參加抽獎**」（還沒加該店 LINE 官方帳號好友時）。兩者**等同參加抽獎**：直接按，不必停下來問使用者，也不必先另外去加好友。（使用者 2026-10-03 指定）
- 按下後若跳出 LINE 的加好友／授權確認，選同意（這一下才算按到參加），然後直接按叉叉。
- 只做「加好友＋參加」這一步：不傳訊息給該帳號、不點選單或優惠券、不封鎖或刪除好友。

## 按鈕缺失時的處理

- LINE 系統有時不穩，參加按鈕可能沒有出現。先短暫等待，再使用該瀏覽器的原生重新整理；重整目標必須是目前抽獎頁。
- 不用「關閉再重開」代替重整，不在未點到參加時直接跳下一項。
- 確認參加按鈕存在、並確定點到它（點擊座標落在按鈕上），就可關閉官方彈窗並進下一項；不必等處理中或結果畫面。
- 不等中獎結果。若進入時就明確顯示先前未中獎，直接關閉。
- 目前尚未驗證 LINE 官方彈窗的原生重整入口；執行時先辨認與驗證，不可宣稱已能重整，也不可刷新背後目錄充數。找不到或重整失敗時保留目前項目並說明卡點。

## 每一輪的操作

1. 點「抽籤」（Agent 模式：固定那一顆；一般清單：最上方綠色那顆）。
2. 留短暫載入時間，點底部「參加抽獎」或「加入好友並參加抽獎」（兩者等同，直接按）。不必等商品圖片載完。
3. 確定按到參加後，直接按官方頁右上角叉叉，不確認結果、不等抽獎結果。
4. 回到目錄：Agent 模式會自動換下一項；一般清單會移除已處理項目，下一項通常補到同一位置。
5. 已經顯示「沒有抽中／未中獎」的頁面直接關閉，繼續下一項。

成功使用過的額外等待參考值：開啟後 1300 ms、關閉後 650 ms；依實際載入速度調整，避免為了快而在空白頁關閉、漏按參加。

## 速度與連續操作

- 使用者偏好連續操作、避免每項都把截圖交給模型重新辨識。版面已確認穩定時（Agent 模式尤其穩定）可用固定座標連續操作。
- **工具能跑腳本化的連續點擊**（例如 Codex 的 `node_repl`）：用可被立即中止的單一連續迴圈，進度通知不阻擋點擊；依工具真實時限設上限，必須分段時立即自動接續。
- **工具一次只能做一個動作**（多數 computer use 類工具）：照步驟逐一執行，但減少不必要的描述與固定等待；不要每 8／10 項停下等使用者指示。
- 每輪可用工具提供的輕量狀態查詢（視窗狀態、無障礙資訊、縮小的截圖）同步，檢查斷線／「iPhone 使用中」訊息，偵測到就立即停止。不要忽略控制工具回報的失敗。
- 這些是效能要求，不代表可略過「確定按到參加按鈕」這一步。累積操作不得超過確認的剩餘數量，完成後查看清單。

## 中斷與恢復

- 使用者說「停止」「停一下」時，立即停止點擊；若有正在跑的腳本迴圈，用工具提供的中斷方式結束它。不要等整批結束。
- 工具回報動作被拒絕、或視窗內容已改變：先重新取得畫面狀態。若仍是已知頁面且被拒動作未執行，可有限次重試；狀態不確定時查看一次畫面並從正確步驟恢復。不要無限重試，也不要一律從開啟項目重來。
- 找不到視窗、畫面擷取錯誤、「iPhone 使用中／請鎖定 iPhone」：停止點擊，確認視窗與連線。不可把斷線解讀為抽完。
- 必須知道目前停在目錄還是抽獎頁；若停在參加畫面，先完成此項並關閉，再進下一輪。
- 頁面、按鈕或清單位置改變，重新確認一次座標，不繼續對未知畫面連點。

## 完成標準與回報

- Agent 模式：看到「本次隊列已走訪完畢」後，按「回一般清單」，再以目前篩選「未抽 0 項」作為目錄處理完成的證據。
- 一般清單：查看一次清單，以「未抽 0 項」及空清單訊息為證據。
- 迴圈跑完幾輪只表示送出了操作，不代表每輪都成功參加。目錄的「已抽」「已走訪」只代表點過，不能證明伺服器已接受參加。
- 若最後仍有未抽項目，按實際剩餘數量繼續，直到完成或出現需要使用者介入的阻礙。
- 不等待結果，因此不要宣稱是否中獎；簡潔回報處理數與未完成項目。

## 實測紀錄

- 2026-10-02 一般清單：開始時目前篩選剩 49 項，結束時「未抽 0 項」，已抽計數 257 → 306。
- 桃園剩餘 99 項，在保留參加觸發和彈窗確認後全部處理完，最終未抽 0 項；途中鏡像斷線一次並恢復。
- 以上皆為 Codex＋Computer Use。Agent 模式與其他 AI 環境尚未實測。原生重整仍未驗證，不得對外宣稱已完成驗證。

## 附錄：各環境備註

- **Codex**（原始實測環境）：使用 `computer-use:computer-use` 技能及 `node_repl` 的 `@oai/sky`，目標 App 為 `com.apple.ScreenContinuity`。中斷迴圈用 `js_reset`，重置後需重新匯入 sky 及建立函式。工具回報 `The user changed ... Re-query ...` 時先重新 `get_app_state`；`noWindowsAvailable` 表示找不到鏡像視窗。每輪可呼叫 `get_app_state` 同步狀態，不必把每次截圖輸出給模型。
- **Claude**（尚未實測）：Claude 的 computer use 是 macOS 上的研究預覽功能，需要 Pro 或 Max 方案（Team／Enterprise 沒有）。Claude 桌面 App 在 **設定 > 一般** 開啟；Claude Code CLI 在互動模式輸入 `/mcp` 啟用內建的 `computer-use`（`-p` 非互動模式不能用）。第一次要給 macOS「輔助使用」與「螢幕錄製」權限，並在提示中允許控制「iPhone 鏡像輸出」這個 App。操作期間其他 App 會被暫時隱藏；按 `Esc` 隨時中止。截圖會自動縮小後才給模型，座標以工具回傳的截圖為準。這類工具一次一個動作，速度比腳本迴圈慢。第一次先測 3 項。說明：https://code.claude.com/docs/en/computer-use
- **其他環境**：只要能截圖並點擊本機 Mac 視窗即可套用本流程；做不到就照「需要的能力」一節回報並停止。
